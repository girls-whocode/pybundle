## 9) Change guide (how to make safe edits)

### When adding a new endpoint

* Add router function in `app/routers/...`
* Update templates/static if UI needs it
* Add validation model/schema
* Add tests
* Update this file section 6

### When changing data model

* Update models
* Add migration (if applicable)
* Update upgrade path (if applicable)
* Update tests
* Document invariant changes in section 5

### When refactoring a complex function

* Split into pure helper functions
* Add unit tests for helpers
* Keep route handler thin
* Preserve response shape & template vars

## 10) "AI operating rules" (copy/paste for assistants)

**Do:**

* Prefer small, reversible PRs
* Keep public API behavior stable unless explicitly requested
* Maintain existing style (imports, naming, formatting)
* Add/adjust tests when behavior changes
* Mention files touched + rationale

**Do not:**

* Delete "unused" route handlers based on static analysis alone
* Change env var names or defaults without updating docs + config
* Introduce new dependencies unless necessary
* Rewrite templates unless you also check their variable contracts

**When unsure:**

* Search for usage across `src/` and templates/static
* Explain tradeoffs and propose the smallest safe change
