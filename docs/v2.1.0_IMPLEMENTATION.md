## 2. Unused Dependencies Confidence Scoring ✅

**Problem:** Unused dependency reports were all-or-nothing. Users didn't know which packages were safe to remove vs. which might be indirect dependencies.

**Solution:**
- Split results into **LIKELY UNUSED** (high confidence) vs **MAYBE UNUSED** (lower confidence)
- Use heuristics to categorize packages
- Check config file mentions

**Confidence Logic:**

**LIKELY UNUSED (safe to remove):**
- Not mentioned in any config files
- Not matching indirect dependency patterns
- High confidence these can be removed

**MAYBE UNUSED (verify first):**
- Matches indirect dependency patterns (setuptools, pytest plugins, type stubs, etc.)
- Mentioned in config files (might be optional/plugin)
- Database drivers (dynamically loaded)
- Web server runners (auto-discovered)

**Technical Details:**
- New `_categorize_by_confidence()` method
- Pattern matching against 20+ common indirect dependency names
- Config file scanning (pyproject.toml, setup.py, requirements.txt)
- New `_is_mentioned_in_config()` helper

**Files Modified:**
- `pybundle/steps/unused_deps.py` (+80 lines)

**Impact:** Makes unused dependency reports actionable instead of just informational.

## 3. AI_CONTEXT.md Auto-Generation ✅

**Problem:** User feedback: "The AI bundle is the closest thing to 'hand the repo to an LLM' but it's missing *how the code thinks*."

**Solution:**
- New step generates comprehensive `AI_CONTEXT.md` automatically
- Implements all 11 sections from user's template
- Uses intelligent auto-detection for project characteristics

**Generated Sections:**

0. **What this project is** — extracted from README, detected framework
1. **How to run it** — auto-detects entry points, run commands
2. **Repository map** — identifies key directories and files
3. **Architecture & patterns** — detects routing, services, middleware
4. **Configuration** — extracts env vars from code, lists config files
5. **Data model & storage** — detects database type, ORM, migrations
6. **API surface** — extracts routes from decorators
7. **Tests & quality gates** — identifies test framework, coverage commands
8. **Sharp edges** — template for manual additions
9. **Change guide** — common task patterns
10. **AI rules** — guardrails for AI-assisted changes

**Auto-Detection Capabilities:**

- **Framework detection:** FastAPI, Flask, Django
- **Entry points:** `__main__.py`, console scripts from pyproject.toml
- **Run commands:** main.py, uvicorn, gunicorn patterns
- **Database:** PostgreSQL, MySQL, SQLite, MongoDB
- **ORM:** SQLAlchemy, Django ORM, Tortoise ORM
- **Routes:** FastAPI `@app.get()`, Flask `@app.route()` patterns
- **Env vars:** `os.getenv()`, `os.environ[]` extraction
- **Migrations:** Alembic directory detection
- **Architecture patterns:** Routers, services, repositories, middleware

**Technical Details:**
- New `AIContextStep` class (680 lines)
- 20+ helper methods for intelligent detection
- Regex extraction for routes and env vars
- File tree scanning with smart exclusions
- Markdown generation with proper formatting

**Files Modified:**
- `pybundle/steps/ai_context.py` (new, 680 lines)
- `pybundle/profiles.py` (+2 lines, integrated into ai profile)

**Integration:**
- Runs in AI profile before `HandoffMarkdownStep`
- Output: `AI_CONTEXT.md` in bundle root
- Step name: "AI context"

**Impact:** Transforms AI bundles from "here's the code" to "here's how to work with this code."
